# SAR Shared Data and Interface Contract: Audio Streaming Profile

Document ID: D01.02  
Document Class: Shared Contract Specification  
Project: Self-Aware-Room (SAR)  
Status: Version 1 draft  
Date: 2026-07-28

## 1. Purpose

This document defines the audio streaming contract profile for SAR edge ingest.

It is a modality-specific interface profile layered on top of the shared edge frame contract. It is not a subclass hierarchy requirement.

## 2. Contract Position

The shared edge frame provides generic transport fields for all modalities.

The audio profile adds audio-required constraints and processing policy.

- Generic frame contract: applies to all L0 producers.
- Audio profile contract: applies when modality is audio.

## 3. Normative Terms

The keywords MUST, SHOULD, and MAY are normative.

## 4. Base Edge Frame

All L0 producers MUST emit a frame with the following base fields:

- source_node_id
- source_id
- modality
- frame_index
- payload

L0 MAY also provide:

- source_capture_time
- source_frame_id
- source_latency_ms

L1 is the canonical ingest authority for SAR object identity and ingest timing.

## 5. Audio Streaming Profile

When modality is audio, the following fields MUST be present on the frame or payload contract surface:

- encoding
- sample_rate_hz
- channel_count
- frame_index
- audio payload content (raw chunk bytes/samples or raw reference fragment)

Recommended optional fields:

- sample_format (for example, pcm16, float32)
- bit_depth
- adc_full_scale_reference
- preamp_gain_db
- transport_crc

## 6. Identity and Time Policy

### 6.1 Identity

- L0 MAY use lightweight source frame IDs.
- L1 MUST preserve source-native frame identity in provenance when available.
- L1 MUST assign canonical SAR object_id values to emitted observation objects.

### 6.2 Timestamp Policy

- L1 MUST stamp receipt_time and processing_time at ingest.
- L0 source_capture_time is optional.
- If source_capture_time is absent, L1 MUST backfill source_capture_time using:
  - source_capture_time = receipt_time - source_latency_ms
- If source_latency_ms is absent or invalid, L1 MUST apply configured default_source_latency_ms.
- default_source_latency_ms SHOULD default to 0.0 unless deployment-specific calibration exists.

This policy allows mixed sensor fleets where some L0 devices provide reliable capture clocks and others do not.

## 7. Audio Gating and Segmentation Metadata

For 24/7 operation, audio capture SHOULD support threshold-aware metadata so storage policy remains auditable.

Recommended payload metadata fields:

- gate_state (open or closed)
- noise_floor_dbfs
- rms_dbfs
- threshold_on_dbfs
- threshold_off_dbfs
- pre_roll_ms
- post_roll_ms
- dropped_by_policy
- capture_policy

Where threshold_on_dbfs and threshold_off_dbfs are relative to the current estimated noise floor, hysteresis SHOULD be used to avoid gate chatter.

### 7.1 Room-Tone Discard Automation

Implementations MAY discard spans that never exceed the adaptive gate threshold above room tone.

If room-tone discard is enabled:

- the system MUST maintain a rolling pre-buffer (ring buffer) to avoid clipping event onset,
- the system SHOULD apply post-roll to preserve trailing context,
- the gate SHOULD use hysteresis (separate open and close thresholds),
- the payload SHOULD record gate decision metadata for audit and tuning.

Recommended starting values (deployment-tunable):

- pre_roll_ms: 300 to 800
- post_roll_ms: 500 to 1200
- threshold_on_dbfs: noise_floor_dbfs + 10
- threshold_off_dbfs: noise_floor_dbfs + 6

These values are relative offsets from current room-noise estimate, not universal absolute loudness thresholds.

### 7.2 Tentative Default Parameters

The following defaults are tentative starting points for implementation and testing.

They are not final acceptance thresholds and MUST be re-evaluated once live room experimentation begins.

| Parameter | Tentative Default | Notes |
| --- | --- | --- |
| pre_roll_ms | 500 | Preserve onset context before gate-open transition. |
| post_roll_ms | 800 | Preserve trailing context after gate-close transition. |
| threshold_on_offset_db | +10 dB over noise floor | Gate-open offset relative to adaptive room-tone estimate. |
| threshold_off_offset_db | +6 dB over noise floor | Gate-close offset relative to adaptive room-tone estimate. |
| default_source_latency_ms | 0.0 | Fallback when L0 does not provide latency estimate. |

These values SHOULD be treated as provisional calibration values pending SAR intake experiments across target rooms and devices.

## 8. Retention and Storage Modes

Implementations SHOULD expose a capture policy switch:

- full: retain all raw continuous audio within configured retention.
- hybrid: retain rolling continuous audio and durable event-linked segments.
- selective: retain event-linked segments and derived artifacts only.

In selective mode, implementations MAY delete raw audio after successful speech/event extraction, provided trace metadata and policy markers are retained.

Recommended retained markers in selective mode include:

- transcript or extracted artifact reference,
- extraction model/version,
- confidence/quality indicator,
- source frame/time interval,
- deletion_reason and retention_policy_id.

Large raw payloads SHOULD be persisted by reference at L1 with checksums and media metadata.

## 9. Interface vs Subclass Guidance

The audio streaming contract is an interface/profile conformance rule.

- A producer implementation MAY use any internal class design.
- Conformance is determined by emitted frame shape and required semantics, not by inheritance.
- New modalities (for example, phone IMU) SHOULD define additional profiles without changing the shared base frame interface.

## 10. Conformance Checklist

An audio L0/L1 path is conformant when:

1. L0 emits base frame fields for each chunk/frame.
2. Audio-required fields are present for modality audio.
3. L1 stamps ingest times and applies latency backfill policy when needed.
4. L1 preserves source-native identity and emits canonical SAR observation IDs.
5. Raw artifacts are retained according to configured storage mode with traceable references.
6. If room-tone discard is enabled, pre-buffer and gate decision metadata are present.

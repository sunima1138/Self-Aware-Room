# SAR Shared Streaming Contract

Document ID: D01.02  
Document Class: Shared Contract Specification  
Project: Self-Aware-Room (SAR)  
Status: Version 1 draft  
Date: 2026-07-29

## 1. Purpose

This document defines the generalized streaming contract for SAR edge ingest across sensing modalities.

It defines the shared envelope, identity, timing, provenance, and conformance rules that all modality profiles must satisfy.

## 2. Contract Position

The shared streaming contract is modality-agnostic and applies to all L0 producers and L1 ingest paths.

Modality-specific constraints are defined by profile documents that extend this contract by composition, not inheritance requirements.

## 3. Normative Terms

The keywords MUST, SHOULD, and MAY are normative.

## 4. Base Edge Frame Contract

### 4.0 Generalized Frame Definition

For this contract, a frame is the smallest ordered transport unit emitted by a producer path for ingest processing.

The frame abstraction is modality-agnostic and supports both:

- clocked sources (regular cadence chunks/samples), and
- event-driven sources (irregular event packets).

General frame requirements:

- A frame MUST carry enough metadata to preserve ordering within a source stream.
- A frame MUST carry source identity, modality declaration, and payload content.
- A frame MAY represent a fixed-duration sample window, a variable-duration sample window, or a discrete event payload depending on modality profile.

The modality profile for a given source class MUST define additional frame semantics and required fields beyond this generalized definition.

All L0 producers MUST emit a frame with the following base fields:

- source_node_id
- source_id
- modality
- frame_index
- payload

L0 MAY also provide:

- source_capture_time
- source_frame_id
- source_latency_ms

### 4.1 Ingest Adapter Conformance (Ingest Boundary Adapter Path)

Some raw intake paths cannot emit all required base frame fields at the source. In these cases, conformance is achieved through an ingest boundary adapter that normalizes source output into the base edge frame contract.

The ingest boundary adapter may run on the source side (L0-adjacent) or at ingest (L1-adjacent), but canonical SAR identity and ingest timing authority remain at L1.

Normative requirements:

- If an L0 source cannot emit all required base frame fields, an ingest boundary adapter MUST construct a compliant base frame before downstream processing.
- The ingest adapter MUST preserve source-native values when available.
- The ingest adapter MUST mark synthesized and backfilled values in provenance metadata so downstream systems can distinguish source-native versus ingest-derived fields.
- Canonical SAR object identity remains assigned at L1 regardless of source capability.

Topology note: multiple L0 producers MAY feed a single L1 ingest node, and this contract does not require one-to-one pairing between L0 and L1.

L1 is the canonical ingest authority for SAR object identity and ingest timing.

## 5. Identity and Time Policy

### 5.1 Identity

- L0 MAY use lightweight source frame IDs.
- L1 MUST preserve source-native frame identity in provenance when available.
- L1 MUST assign canonical SAR object_id values to emitted observation objects.

### 5.2 Timestamp Policy

- L1 MUST stamp receipt_time and processing_time at ingest.
- L0 source_capture_time is optional.
- If source_capture_time is absent, L1 MUST backfill source_capture_time using:
  - source_capture_time = receipt_time - source_latency_ms
- If source_latency_ms is absent or invalid, L1 MUST apply configured default_source_latency_ms.
- default_source_latency_ms SHOULD default to 0.0 unless deployment-specific calibration exists.

This policy allows mixed sensor fleets where some L0 devices provide reliable capture clocks and others do not.

## 6. Payload and Reference Policy

- payload MUST contain either in-frame values or a valid reference descriptor to persisted raw content.
- Large raw payloads SHOULD be persisted by reference at L1 with checksums and media metadata.
- Reference descriptors SHOULD include enough fields to support replay and audit.

## 7. Interface vs Subclass Guidance

The shared streaming contract is an interface/profile conformance rule.

- A producer implementation MAY use any internal class design.
- Conformance is determined by emitted frame shape and required semantics, not by inheritance.
- New modalities SHOULD define additional profile documents without changing this base contract.

## 8. Profile Extension Model

Modality profiles MUST define additional required and optional fields for a specific modality while preserving this base contract.

Current profile set:

1. D01.02.01 Audio Streaming Profile.

Planned profiles may include video, depth, IMU, and other sensor classes.

## 9. Conformance Checklist

A producer path is conformant when:

1. L0 emits base frame fields for each frame in source order.
2. Modality profile required fields are present for the declared modality.
3. L1 stamps ingest times and applies latency backfill policy when needed.
4. L1 preserves source-native identity and emits canonical SAR observation IDs.
5. Raw artifacts are retained according to configured storage mode with traceable references.

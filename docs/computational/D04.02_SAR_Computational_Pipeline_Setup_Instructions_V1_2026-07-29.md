# SAR Computational Pipeline Setup Instructions

Document Class: Tooling and Operations Setup  
Project: Self-Aware-Room (SAR)  
Status: Draft  
Version: V1  
Date: 2026-07-29

## 1. Purpose

This document explains how to set up and run the baseline SAR computational pipeline in a repeatable local development environment.

The instructions are aligned to the current L1 through L5 plus O1 vertical-slice scaffold in src/sar_core and src/sar_apps.

## 2. Scope

This section defines what this setup guide covers so teams can execute the baseline quickly.

In scope:

- local Python environment preparation,
- source-path execution for the SAR pipeline demo,
- runtime artifact locations,
- verification checks for successful setup,
- common failure modes and fixes.

Out of scope:

- production deployment,
- distributed edge-node provisioning,
- advanced sensor hardware integration.

## 3. Preconditions

This section defines the minimum assumptions before running commands.

1. You have a local clone of the repository.
2. You can run Python 3.12 or newer from your shell.
3. You are running commands from the repository root.
4. You have write access to runtime/logs and runtime/raw_observations.

## 4. Repository Paths

This section identifies the key files that make up the baseline setup.

1. src/sar_apps/pipeline_demo.py: runnable vertical-slice demo.
2. src/sar_core/pipeline.py: default pipeline constructor and L1-L5 flow.
3. src/sar_core/contracts/: shared data contracts and schema-like objects.
4. src/sar_core/stages/: stage implementations and observability component.
5. runtime/logs/: O1 JSONL event logs.
6. runtime/raw_observations/: persisted raw observation payloads.

## 5. Environment Setup

This section provides a minimal local setup process using source execution.

### 5.1 Verify Python

This subsection confirms the interpreter meets baseline requirements.

Run:

```bash
python3 --version
```

Expected:

- Python 3.12.x or newer.

### 5.2 Optional Virtual Environment

This subsection provides an isolated environment option for contributors.

Run:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

Note: The current vertical slice uses only standard-library dependencies for core execution.

### 5.3 Set Import Path

This subsection ensures local package imports resolve without installing a wheel.

Use PYTHONPATH=src when running examples and tests from the repository root.

## 6. Run the Baseline Pipeline Demo

This section runs the canonical local validation entry point.

From the repository root, run:

```bash
PYTHONPATH=src python3 src/sar_apps/pipeline_demo.py
```

Expected high-level behavior:

1. L1 through L5 stages report StageStatus.OK.
2. L3 emits state and event objects.
3. L5B emits at least one dispatch object.
4. O1 reports record count and log file path.

## 7. Validate Runtime Artifacts

This section confirms the pipeline persisted expected outputs.

### 7.1 O1 Event Log

This subsection validates observability output.

Check:

- runtime/logs/o1_events.jsonl exists,
- file includes stage status and transfer events.

### 7.2 Raw Observation Storage

This subsection validates acquisition persistence.

Check:

- runtime/raw_observations contains timestamped JSON files,
- L1 output includes raw_ref_uri values pointing to stored files.

## 8. Troubleshooting

This section captures common setup issues and direct fixes.

### 8.1 ModuleNotFoundError for sar_core

This subsection addresses import-path failures.

Fix:

```bash
PYTHONPATH=src python3 src/sar_apps/pipeline_demo.py
```

### 8.2 Permission Errors Writing Runtime Files

This subsection addresses filesystem write failures.

Fix:

```bash
mkdir -p runtime/logs runtime/raw_observations
chmod u+rwx runtime runtime/logs runtime/raw_observations
```

### 8.3 Unexpected StageStatus Values

This subsection addresses behavior drift and schema mismatches.

Fix sequence:

1. Run the demo again with a clean shell session.
2. Inspect latest records in runtime/logs/o1_events.jsonl.
3. Verify local changes to src/sar_core/contracts and src/sar_core/stages.

## 9. Team Workflow Baseline

This section defines the recommended setup and validation workflow before opening a merge.

1. Pull latest main.
2. Run the baseline demo.
3. Confirm runtime artifacts were generated.
4. Run relevant unit or integration tests when available.
5. Include setup deviations and assumptions in your change notes.
